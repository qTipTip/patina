

## Learning about phantom tags

> Music of the day: [Deep Progressive Techno #15](https://www.youtube.com/watch?v=FwQ_Pc_uwcQ).

I've currently tried to shoehorn the inheritance architecture from PBRT into a
rust codebase. I'm already starting to feel the pain from this.

Currently, I've created a Tuple3 class that holds (x, y, z). I've then created
classes "Vector3", "Point3", "Normal3", that all are tuple structs with one
field, a Tuple3.

Now, this doesn't automatically give a Vector3 all the methods on Tuple3. To
fix this I implemented "Deref coercion" by implementing the Deref and Deref mut
traits. 

This allows you to call into methods on the underlying type automatically.
However, you're losing the typing here! If I call `v.some_method_on_tuple()`.
However, the docs warn against this, by saying you should not use deref
coercion unless the type you have is a transparent wrapper of the inner type.

An example of this would be Box<T>, which transparently holds a T, and I would
like to be able to use it as a T.

This breaks down when I say that a Point transparently is a Tuple, because they
are not.

## How do we solve it? 

We can use something called `phantom tags`. We can use it to "tag" our Tuples.
